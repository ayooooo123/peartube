# Durable MediaStorm Ingest Jobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Acquire one selected non-PearTube source out of band through a completed spool or authenticated resumable MediaStorm callback and publish it exactly once.

**Architecture:** The companion persists a non-secret job fingerprint and state machine keyed by caller-provided `Idempotency-Key`. Completed spool/file transfer is preferred. Fallback uses a 256-bit MediaStorm source capability bound to companion identity, job ID, immutable ETag, exact length, and expiry; the companion redeems HEAD/GET ranges and deletes the capability at every terminal state.

**Tech Stack:** CLI companion API, existing archive manager/job store patterns, streaming multipart, Go `net/http`, MediaStorm playback resolver, Brittle, Go tests.

## Global Constraints

- Depends on Plan 10 authenticated control and stream behavior.
- Active playback is never proxied, rerouted, delayed, or cancelled by ingestion.
- The durable job fingerprint excludes URLs, cookies, headers, capabilities, and credentials.
- Same idempotency key plus same canonical body returns the same job; a different body returns `409`.
- Redirects, DNS rebinding, private/loopback destinations, length drift, and ETag drift fail closed.
- `publicInfohash` is accepted only with an explicit tracker-independent/public attestation; private tracker IDs and passkeys are rejected.
- Terminal completion, failure, cancellation, or expiry deletes capability and in-memory URL material.
