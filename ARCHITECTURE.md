# PearTube Architecture

## Overview

PearTube is a decentralized P2P video platform that runs from one monorepo across:

- iOS/Android via Expo + BareKit
- Desktop via Pear Runtime (`pear-electron` + worker)

## Monorepo Layout

```text
packages/
  app/        Unified frontend app + platform launch glue
  backend/    Core P2P/business logic (orchestrator, storage, swarm, API)
  core/       Shared app types/components/hooks
  platform/   Runtime bridge (rpc.native.ts / rpc.web.ts)
  spec/       HRPC schema + generated client/server bindings
  bare-*/     Native/runtime support packages (ffmpeg/mpv/cast/tls)
```

## Runtime Architecture

### Mobile

```text
React Native UI
  -> @peartube/platform/rpc.native
  -> BareKit Worklet (backend.bundle.js)
  -> @peartube/backend
```

### Desktop

```text
Expo web export in Pear window
  -> worker-client bridge
  -> Pear worker (pear-src/workers/core/index.ts)
  -> @peartube/backend
```

## RPC/Handler Model

- Wire protocol is generated by `@peartube/spec`.
- Backend-side handlers are registered through `packages/backend/src/hrpc-handlers.js`.
- Backend entrypoint (`packages/backend/src/backend-entry.js`) now registers shared handlers immediately after HRPC creation.
- Handler registration is capability-based (only registers methods that exist on current HRPC runtime), which avoids startup crashes when optional methods are absent.

## Startup/Readiness

- **Mobile:** startup can use `eventReady` or status probe fallback. Missing downloader worker bundle no longer blocks backend boot.
- **Desktop:** worker starts backend, registers handlers, then begins serving RPC/event traffic.

## Build Pipelines

### Mobile backend bundle

```bash
npm run bundle:backend
```

Generates:

- `packages/app/backend.bundle.js`
- `packages/app/downloader-worker.bundle.js`

### Pear desktop build

```bash
npm run pear:build
npm run pear
```

`pear:dev` uses `pear run --dev` (the old `pear dev` command is removed in current Pear CLI).

### Android release

```bash
npm run build:android:apk
npm run build:android:aab
```

Release scripts run Android prebuild first, restore/write `android/local.properties`, then run Gradle.
