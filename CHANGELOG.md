# Changelog

## Unreleased

- Restore callback acquisitions through the existing shared Web UI/API port. Non-loopback source-grant requests now require verified request signatures even when public API authentication is disabled; modified and replayed grants remain rejected. No route or listener was added. Use runtime-specific OS imports so the current console can be packaged in the Bare relay executable.
- Make an explicit publisher follow reach a real mobile catalog. The policy runtime now turns a followed publisher ID into a bounded follow reason and accepts only the signed bootstrap locator plus namespace proof that resolve it; it no longer exposes a field the backend rejects as unsupported. Serving devices now announce the metadata-only bootstrap scope, while watch-only devices remain client-only and bootstrap authorization still cannot serve catalog or media bytes. A live Android client followed the relay publisher, accepted its locator, completed the verified publisher follow, and rendered `Furious` and `Lanterns`.
- Restore watched-media ingest through reciprocal source grants. The relay now receives callback origin, client, and shared-secret configuration; carries the actual opaque capability into range reads instead of the registry parameter object; and can reopen jobs poisoned by that retired internal shape. A client can fall back from unavailable direct-URL classification to its range-readable stream provider. A segment closed by the consumer stops a retry instead of passing a typed-nil writer into a downstream pool and crashing the process. Automatic duplicate detection now uses authenticated exact `/api/v2/search`; it no longer scans the legacy `/api/v1/catalog`. A live watched episode submitted through that standardized path and is transferring under a contribution-cache job with measured byte progress.
- Show standardized machine-ingest work in the relay console instead of reading the retired archive-job store, so current transfers and failures are visible under Recent additions. Resume now migrates a version-one staging identity only when its nonempty ETag exactly matches the current source, using the current verified length to write the version-two record; an unknown or changed source still fails closed instead of trusting staged bytes.
- Complete removal of the retired local media index by deleting its stale barrel export; current source no longer aborts at startup after the module file was removed. The operator console and authenticated v2 machine API now use separate listeners instead of attempting to bind the same port.
- Add Oxlint’s ESLint-compatible cyclomatic complexity pass to the root lint workflow. Product JavaScript and TypeScript report classic complexity above 20 as a warning; default Oxlint categories and plugins are disabled so this pass measures only complexity, while generated schemas and syntax fixtures that Oxlint cannot parse are excluded. The focused product-source baseline is 369 warnings across 163 files, and `--max-warnings 369` makes any net increase fail lint while existing debt remains visible.
- Make the relay inventory read like what it is: a decentralized debrid, where a work groups many archived releases rather than one row. The acquisition contract now projects the work title, its media coordinates and the file name the archival source gave the file, so a transfer is named by its release instead of `Acquisition ing_…`. The shelf lists every publication under a title with its own size and proven backup count, and a transfer row carries verified progress, the retained byte total, retention class, coordinates and durable publication identity. Rates and ETAs stay absent because the acquisition service exposes no sampled rate, and inventing one from a lifetime average would be a lie. A relay migrated before the identity was carried is backfilled on the next start: the legacy record's coordinates are mapped from both retired shapes onto one whitelist, its file name is reduced to a basename, and a job that already names its work is never overwritten.
- Replace the relay's single-scroll archive page with an operator console for a debrid node. `/` is now one dense table whose row is a release — one archived file with its own bytes, residency and proven backups — with a Work column, group-by-work, state chips, retention filter, free-text search, sortable columns, checkbox selection and bulk cancel, a detail drawer, and `/` and Escape shortcuts. Default order is what needs attention first: transfers in flight, then retryable failures, then the shelf by recency. Filtering, sorting and paging run on the relay because a node that auto-seeds continuously holds hundreds of releases; the four-second poll fetches the same query as a row fragment, so the page and the poll cannot disagree. Discover, creators and settings became real routes, and the shelf cards, transfer list and helpers only they used are deleted rather than left behind a dead flag. The header reports releases, active, failed, unbacked, peers and bytes held, where held counts verified bytes of finished releases plus bytes accepted in flight and never a failed attempt's expected size. A publisher names its own files, so the bootstrap projection escapes every `<` and the drawer escapes everything it writes as HTML.
- Keep catalog presence, current reachability and local residency apart in the relay console, as the relay contract requires. Size is the length a signed manifest claims and says nothing about this disk; Reach is the media catalog's own availability assessment, reported as complete over independent peers with its state, observation time, expiry and reason codes; Backups stays the count of independent archivists; Residency is a separate column, proven rather than inferred, and a catalogued release with no proof reads `Unproven` rather than `Local`. Progress is this relay's accepted bytes, so a catalogued release it never fetched shows no progress instead of 100%. Held counts the full length of locally resident releases plus bytes accepted in flight, and refuses to count a dead attempt's partial bytes because the relay does not report how much of one it kept. On the live relay this moved held from a claimed 65.7 GB to the 187 MB it can prove, and marked its two catalogued titles `Unproven` with reach `NEVER_ASSESSED`.
- Prove local residency instead of inferring it. `api.getLocalRangeResidency` reads the local bitfield for a publication's rendition — `core.has()` over the required ranges, opening no connection and pulling no block — and the relay console runs it over the whole shelf before it filters, sorts or pages. Residency is a sortable column and a header counter, so proving it after the query would sort stale values and report totals that mixed probed rows with unprobed ones; the pass is bounded to 256 probes per request with eight in flight and a thirty-second cache, and a row past that budget says it was not probed rather than reading as absent. Catalog availability and `candidateRef` are not accepted as proof: the first is evidence about peers, the second comes from an index search. `offlinePlayable` is not read either, because nothing calls `recordLocalRanges`, so the field is structurally always false. A relay with S3 block offload restores evicted blocks from the bucket on read, so a local miss is reported as unmeasured rather than as loss, and per-release offload residency remains an open capability. On the live relay this is the difference between a console claiming two titles are `Local` at `100%` and one reporting that its volume holds none of their ranges while it seeds ~91 MB against a 6.4 GB catalog.
- Name the episode a release belongs to. The media catalog never projected media coordinates at all, so every reader of `source.mediaCoordinates` in the relay was reading a field that did not exist: the console showed no season or episode, TMDB discover could not match a catalogued title, and the index search that mints `candidateRef` never ran, which silently removed playback links from catalogued rows. `listEntities` now carries each work's signed external references, and the catalog projects them as coordinates — an episode reference (`show:<mediaId>:s<season>:e<episode>`) becomes a season and episode, a plain reference becomes a film or a show with its year, and a work nobody cross-referenced carries none rather than a guess. The console's Work column shows the show and the episode together, and the full coordinate stays searchable and in the detail drawer.
- Make the console's job verbs do something and say what they did. Cancelling a finished acquisition was always a no-op in the manager, and the console refreshed silently, so it read as a broken button; there was no way to clear a dead record at all. The durable acquisition store gains `forget`, which deletes a finished job with its event log and its idempotency index — leaving that index behind would point a replayed request at a job that no longer exists and fail the store as corrupt — and refuses anything still running. It is exposed through the acquisition manager, the provider service and the relay service, and the console offers Cancel for running work, Clear for finished work, and reports per job what happened: `1 cleared`, or `0 cancelled; 1 refused: ing_ff0ac717 already failed`. The bulk bar's old `Clear` button, which only cleared the selection, is now `Deselect`.
- Stop the relay refusing every authenticated search. The companion route spread the caller's `principal` into the provider search request, but `providerService.search` validates against a closed field list, so it failed with `INVALID_FIELD: request.principal is unsupported` and the companion mapped that to `502 BACKEND_ERROR`. Every `/api/v2/search` from every machine client had been failing that way, which also took out duplicate detection and auto-seed catalog checks in connected applications. The principal authorizes the call and never rides in the query. The route test fake now enforces the provider's real field list, because a fake that shrugs at unknown fields is what let this ship.
- Answer `/api/v2/policy` instead of refusing it. The provider subsystem took an optional policy adapter that no node ever supplied, so every read or write of the participation policy failed `POLICY_UNAVAILABLE` and an operator could see a relay's transfers but never its posture. The orchestrator now adapts the node's own `policyApi` onto the provider's seam: reads return the live network policy, writes carry an expected revision that counts accepted writes since boot, a stale writer is refused rather than silently overwriting, and a rejection keeps the field name the policy surface named. A node without a policy surface still gets no adapter rather than a broken one.

- Make cloud archival one honest path: S3 block storage is the only offload backend, and the objects it writes are the objects the relay restores and seeds. Delete the speculative Google Drive and Mega clients, their provider-selection config, and the separate whole-file S3 upload that read a completed title into memory and produced an object the seed path never used. Also delete process-local upload/offload totals from operator status: they reset on restart and counted temporary staging traffic, so they could not prove durable inventory. Status now reports only the configured resident window, measured local residency, and restore activity; outbound P2P work is named `activeServes`/`servedBytes` so it cannot be mistaken for media ingest.
- Make locally held publications visible to client application without a remote indexer. Companion v2 search previously federated only retained network index services, and returned an empty list before consulting the same publisher catalogs that `/api/v1/catalog` could already stream. The backend now keeps a bounded durable local index, backfills persisted verified catalogs at startup, refreshes it on catalog changes, and offers it to the existing federation as an in-process service. The legacy bridge derives a publication’s work identity from its signed publication-bound claims when an older manifest has no claim links. Verification now reads real catalog accepted entries with their writer-provenance prefix, treats an Autobase view key as distinct from the catalog bootstrap key, and accepts a current signed publication-bound claim when a legacy manifest has an empty claim list. Local custody is proved by reading a block through the normal S3-aware Corestore path; remote candidates still require network evidence. Stream opening trusts the manifest attached only by the source verifier instead of applying the root-only verifier to a valid device-writer signature. Exact episode coordinates survive URL sanitization. Live checks returned one Lanterns S01E02 candidate and HTTP 206 for bytes 0–1023 through companion v2; no v1 fallback or client application-side search path was added.
- Make client application’s manual source picker show the PearTube result it already had. The server now recovers the canonical TMDB series ID from metadata when installed clients send only IMDb, keeps one passed result from every playback service inside the presentation cap, and surfaces those service representatives directly after the top-ranked result. The broken admin path now declares `pearTubeStatus`, registers its status route, and tests PearTube as PearTube instead of falling through to Torrentio. Relay custody and range reads now call the S3-aware Corestore `get` path when an offloaded block is absent from the local bitfield, rather than declaring the verified local publication unavailable. A live Android search placed `lanterns S01E02 [PearTube]` on the first source page; selection resolved in 737 ms and client application read HTTP 206 ranges from the relay.
- Carry cover art through the machine API, not just the console form. `fetchPosterBytes` exists because a consumer holds no metadata-provider credentials: art has to be published with the record, or every catalog renders as blank placeholders and a provider URL in the claim would make browsing reach an origin outside the swarm. The browser form has always sent `tmdbPosterPath`; `POST /api/v1/archive` silently dropped it, so everything an automated publisher seeded - which is every title a client application library mirrors - was published with no cover at all. The field now reaches the same job the console builds, and the publisher fetches the image once. It is validated rather than normalized, because this value chooses an outbound request: a TMDB file path is accepted, and a full URL, a nested path, a traversal or an overlong name is refused with `INVALID_POSTER_PATH` instead of being coerced into something that happens to work.
- Let a relay be configured from its config file, and let an operator ask for custody to be confirmed. `peartube-relay ui` passed its own fallbacks in as command-line values, which outrank the file they were meant to fall back to, so `archive.uiHost` and `archive.uiPort` in a config were dead settings: every relay started from a file bound `0.0.0.0:8174`, and a second one on the same machine died with `EADDRINUSE` while its own config named a free port. Only what the operator actually typed overrides the file now. The archive challenge cadence has the same shape of problem in a place that matters more: the backend has always accepted `challengeIntervalMs` and `challengeTimeoutMs`, and the relay never passed either, so possession was re-checked every five minutes and nothing else was possible — an operator could not tighten it, and no test could watch an archivist prove custody without reaching into the runtime by hand. Both are relay config now, with out-of-range values dropped rather than clamped so a typo cannot become a hot loop against a peer. With a five-second cadence, a mirrored publication reports `withArchivistEvidence=1` forty seconds after it is seeded, where it previously reported zero indefinitely.
- Let a followed catalog survive a second walk, which is what a viewer's own retry always is. A publisher served the first page of a session and then refused every later page whose linkage restarted, so a locator refresh, a retried walk after a truncated one, or a moved head killed the session; the consumer reported `PUBLISHER_CATALOG_PEER_DISCONNECTED` and the scope was then stranded, because the locator had not moved (so the follow scheduler skipped it), the topic was already joined (so no connection event re-attached it), and re-joining a scope only ever attached peers when it created one. A desktop client that lost its catalog peer once stayed empty for the life of the process, and only an unrelated second peer connecting ever broke it. Restarting a page sequence is now allowed - pages within a sequence still chain, and the per-session budgets keep accumulating across them, so a restart buys a peer nothing - and re-joining a scope re-attaches the connections already open. The regression test closes one protomux channel while leaving the stream and its bootstrap channel up, because the connection surviving is the whole point: with the stream torn down instead, the existing code recovers on the next connection event and the defect cannot reproduce.
- Run the backend suite. `test/identity-recovery.test.mjs` called `process.exit(0)` on success, and every file in that directory shares one brittle process, so the run ended at the letter i and reported success — while a third of the suite never executed. Two of the files it was hiding tested APIs that no longer exist: `assessUploadOffload`, removed with the legacy data plane, and the comments/reactions group, unwired from `api.js` at the same time. Each threw a `TypeError` from an async path brittle could only report as "asynchronous activity after the test ended", and each one aborted the rest of the run. Those three files now report through brittle instead of an exit code, and the tests for the removed APIs are gone rather than left to poison the run. The suite executes 196 tests where it executed 61, and its nine remaining failures are now visible rather than silently skipped.
- Stop the watch screen making two false statements about a title that is playing. A 179,775-byte video pulled entirely from one synced peer showed `recently · 0 B` and `Starting player…` while frames were on screen. The size was never plumbed: `getMediaEntity` returned a hardcoded empty rendition list even though the wire schema already carried `byteLength`, so the player formatted `undefined` as `0 B`. It now carries the size of the rendition Play actually started, and every surface omits the segment when the size is genuinely unknown rather than printing zero. The status line reads real player state: `Playing` while it plays and `Paused` once it has advanced past the start, because stats never arrive at all for publication playback and their absence was being rendered as "still starting" for the entire life of a paused or finished title.
- Stop asking a device with no personal store to hold watch progress. A fresh install whose keychain refuses the personal-store secret has no writable store at all, so every ten-second progress tick threw `No writable personal store` inside the backend — and every backend throw is reported on the host error channel, which put `[App] Backend error` in front of the viewer several times a minute while a video played perfectly well. The player now skips the write when provisioning left this device without a store, and swallows the rejection on the promise it gets back rather than in a synchronous `catch` that never sees it. The backend answers that one best-effort call with a structured `{ success: false }` refusal instead of throwing; creating a playlist, adding to one, and setting a setting still throw, so an explicit action still fails loudly.
- Stop retrying a source the player cannot decode. A 400KB file of filler bytes named `.mp4` made media3 fail extractor sniffing, and the player treated that like a stalled range request: it re-attached the source, re-read all 409,600 bytes from the peer, got the identical rejection, and repeated every two to four seconds for as long as the screen stayed open — while the overlay claimed it was still connecting. Player failures are now classified against the one playback error vocabulary before anything is retried, structured evidence first: a code the app already speaks, then the `MediaError` number, and only then the demuxer's own tokens for Android and iOS, where expo-video forwards a message and no code at all. A container or codec that cannot be read is terminal — it latches, every automatic path that would fetch or re-assert playback stops, the session ends, and the viewer is told the source cannot be played. Peer timeouts, disconnects and session pressure still retry inside the existing four-attempt budget, and a failure we cannot name still retries there rather than being guessed terminal.
- Send the core manifest with every block proof this transport serves, so relay-to-relay byte custody actually completes. An archivist opens the pledged core from its key alone, so its Hypercore cannot resolve the signer of the tree signature and refused every served proof as unsigned: `applyProof` threw inside the chunk handler, the archivist's core stayed at length zero, the possession challenge answered "challenged archive block is not locally retained", and offload evidence never rose above zero — the whole re-seeding story stopped one hop short of a byte moving. The manifest is self-authenticating, the core key being its hash, so it now travels with the proof exactly as hypercore's own replicator sends it to a peer that lacks one. Two suites straddled the gap without catching it: the real-Corestore custody test pipes `store.replicate()` so hypercore's replicator moved the bytes and this transport never ran, and the scoped-runtime test runs the transport against mock cores whose `applyProof` records whatever it is handed. The new coverage connects two runtimes over a duplex pair with real Corestores and no replication between them, so nothing but archive frames can move the content.
- Drop protected/DRM media from the product entirely. PearTube distributes public content only, and there is no entitlement, license, provider-authentication or content-key concept left in the app, the protocol, the relay or the plans. The rival `UNSUPPORTED_DRM`/`DRM_UNSUPPORTED` reason codes, the `LICENSE_DENIED`/`LICENSE_EXPIRED` playback errors, the `drmSystem`/`encryption` projection fields, and the `authentication`/`license` control-plane traffic classes are gone rather than disabled — with no license service to talk to, an outbound request to one is now classified as a forbidden origin, so strict-P2P got stricter.
- Make relays re-seed each other. A relay that publishes a rendition now also publishes a signed archive request for it, and is an archivist by default: it accepts other relays' requests inside its capacity, downloads the pledged ranges, retains them, and answers possession challenges — so content stops depending on the machine that first published it. Capacity is the storage guard's own headroom floored at the bytes already pledged, because shrinking it below them would release every live pledge; `--no-reseed` never calls into participation at all rather than passing a disabling flag. Status reports both directions in measured numbers: what this relay asked the network to mirror and how many independent archivists hold fresh evidence for each, against what it is mirroring for others and the bytes that costs.
- Teach the participation decision what kind of machine it is running on. A headless relay has no battery, no thermal throttle, no metered link, no app lifecycle and no playback window, so those are reported as not-applicable rather than unknown — an unread signal on a real device still fails closed, and an explicitly reported bad one still stops a server. Disk stays measured from a real `statfs`, and a host that cannot read its own disk refuses custody instead of guessing. A full disk now stops a relay writing without silencing what it holds: serving a block is a read, so muting a nearly-full relay would delete availability from the network and free nothing. The one-tenth-of-the-volume floor is a courtesy to someone whose phone feels full and no longer applies to an archive host that was bought to be filled; the absolute floor that protects the machine itself still does.
- Add `peartube search` and `peartube get`. The consumer CLI joins the network headless, reads the same catalog projection the app reads, and prints each hit's availability and independent peer count verbatim — omitted entirely when the network has not reported them, never rendered as zero and never restated as durability. `get` streams a rendition to a local file over P2P only, resumes from a verified partial rather than restarting, refuses to place a file whose length disagrees with the signed manifest, and exits `AVAILABILITY_BOUNDARY` when no peer serves the required ranges. No HTTP media path exists on either command, and neither needs a relay running or an account.
- Let all three metadata authorities actually categorize the network. TMDB reached end to end for movies and episodes; TVDB was a declared namespace that ingest refused by name; MusicBrainz had reference namespaces no publication could ever reach, because the content kinds stopped at video. One table now says which authority may categorize which kind of work and the exact coordinate shape that pairing takes, and the validator, the identity key, the upload contract and the CLI all read it — so `peartube add --type track --provider musicbrainz --recording-id` works, and adding a fourth authority is a table entry rather than four edits. A coordinate a kind does not have is refused rather than stored empty: a track cannot carry a season. TMDB identity keys are byte-identical to the ones already published, because they are durable idempotency identities and a tidier scheme would orphan every import in the network.
- Carry genre, release year, runtime and overview into the permissionless catalog and let the CLI filter on them. `peartube search --kind track --genre Jazz` narrows the same projection the app reads before the result limit applies, echoes what it filtered on, and prints a category only where one was claimed. One bounded normalizer now runs on ingest and on both read paths, because a claim signed by another publisher never passed through this publisher's ingest — which is how an over-described publication used to disappear outright: the local index rejects a record carrying more than eight genres, so a publisher claiming thirteen deleted their own title from every consumer's catalog instead of over-reporting.
- Give TVDB and MusicBrainz real metadata clients, so all three authorities behave alike and `--title` is no longer the price of publishing outside TMDB. One registry derives each authority's kinds from the coordinate table rather than restating them, and a title is now required only when the authority genuinely cannot be read — the refusal says which case it is, because "TVDB needs `PEARTUBE_TVDB_API_KEY` configured" and "no client exists for this authority" are different problems with different fixes. TVDB exchanges its key for a bearer token once, caches it, and re-logs in exactly once on a 401 rather than looping; the key never reaches a URL or an error message. MusicBrainz needs no credential but does need manners: every request carries a descriptive User-Agent that cannot be blanked away, and a serialized queue holds it to roughly one request a second. Genres come from the release group, which is the only place MusicBrainz actually keeps them — a release reported none while its group listed eleven — and a title with none anywhere reports none rather than an empty list. Cover art is a separate service, so its absence is a normal 404 and never an error, and its `http://` URLs are upgraded before they are stored.
- Cover relay-to-relay archive custody at both levels, because they answer different questions. The discovery wire is exercised over two runtimes end to end — a relay publishes an archive request, the second evaluates it against its own participation decision, accepts, reserves capacity and pledges, the first challenges a randomly chosen block, and the pledge only becomes offload evidence once a proof comes back. That test runs on mocked cores, so it proves the protocol is wired and nothing at all about whether a byte moved; the accompanying real-Corestore coverage proves that separately. A pledged range is genuinely replicated onto the archivist — zero blocks before, every block after, byte-identical to the publisher's — and possession is a real Hypercore Merkle proof, refused when it is corrupted, when it is a perfectly valid proof of a block nobody asked about, and when the archivist reaches past the range it signed for.
- Prove the property that makes evidence-gated offload honest rather than wishful: an auditor holding none of the content can still verify that an archivist holds it. The auditor registers the pledged range without downloading a single block, keeps only the signed tree, and checks the archivist's proof against it. Without this, a relay that deleted its own copy could never tell whether anyone else really had one, and "durability evidence" would mean only that a peer once said yes.
- Pin what an archivist does across a restart, since nobody is watching when a relay reboots and an archive pledge is a promise to someone else. Custody it still owes survives: the reservation comes back and the range is re-retained, so the promise is live again rather than merely remembered. Custody whose retention lapsed while the process was down is released on the way up — the ledger is cleared and the capacity genuinely returns, instead of an expired promise quietly occupying the disk forever. And a relay booted with re-seeding switched off releases persisted custody rather than keeping bytes for a challenge it will no longer answer.
- Fix asynchronous P2P archive discovery and manifest resolution between live relay nodes: unfulfilled local archive requests now re-broadcast periodically (every 15s) and immediately when a new peer session activates on the `archive-discovery` topic, ensuring requests published before peers connect are received. `authorizeArchiveRequestFromManifestStore` now dynamically updates the consumer media catalog projection when a manifest is not yet in the local asset store, allowing an archivist relay to resolve and verify incoming publication manifests as soon as it follows the publisher.
- Replace the unauthenticated global-feed prototype with a permissionless media CDN architecture: publisher-scoped catalogs and asset topics, signed immutable rendition/publication manifests, deterministic media-entity resolution, bounded peer admission and multi-peer scheduling, explicit curator/index/moderation feeds, epoch-scoped live delivery, archive pledges with possession challenges, evidence-gated source offload, local trust/retention/privacy controls, portable public-state recovery, and structured operability diagnostics now run through the universal backend on mobile and desktop.
- Add shell-custodied publisher roots: mobile keeps roots in authenticated Expo SecureStore, desktop keeps them in the Bun main-process OS keyring, and renderers/backends receive only bounded single-use signing intents. Publisher namespace, writer admission/revocation, rotation, and recovery records now apply through a deterministic Autobase/Hyperbee catalog with exact source, sequence, capability, replay, cutoff, receipt, and bounded-journal enforcement.
- Migrate legacy publisher roots through an offline privileged preflight before normal Corestore startup. The source is deleted only after the shell vault durably imports it and signs the exact domain-separated continuity challenge; denial, invalid input, lock contention, interruption, or persistence failure preserves the source for retry.
- Harden archive custody and destructive source offload: archive requests, pledges, and challenges are signed, replay-bounded, and authorized against exact rendition ranges; retained capacity is durably reserved and restored across restart; active playback and prefetch ranges are serialized against deletion; offload now requires complete independently verified source coverage, immutable publication identity, a fresh evidence-bound confirmation that rejects clocks before issuance, and explicit irrecoverability acknowledgement; storage-limit previews fail closed when protected archive or playback bytes make eviction infeasible.
- Fix physical Android startup and profile pairing after the permissionless-CDN cutover: the backend lifecycle now supplies an exception-safe abort signal on Bare runtimes that do not define `AbortController`, and the composed backend API now includes its extracted pairing/device methods so `listDevices`, invite creation, and device sync no longer fail through HRPC.
- Remove ad-hoc `udx-native` construction from mobile, desktop, Chromecast, and mDNS Cast address discovery. Targeted Cast routes now select the receiver's matching subnet from Holepunch `bare-os` interface data, while mDNS and Chromecast bind from the same runtime interface source; this avoids creating unrelated UDX transports or unreliable connected-UDP probes solely to choose a LAN address.
- Preserve Android autoplay across the transient native pause emitted while replacing a video source. The player now guards the bounded startup handoff, reasserts native play until a real playing event arrives, and cancels retries on explicit pause, close, or successful playback.
- Redact bearer capabilities from backend, Cast, transcode, playback, download, and search diagnostics. Cast proxy path tokens and blob-server query tokens now pass through one tested sanitizer, credential-bearing playlist/curl dumps are removed, raw search result objects and user queries are not logged, and the unused pseudo-auth blob token was deleted.
- Restore direct P2P playback discovery guarantees: remote blob cores are opened with Corestore key options, and each first-range warmup keeps Hypercore peer discovery alive for a bounded lease so on-demand blob-server reads can establish peers without turning playback into a full-file prefetch.
- Connect native and web media, collection, and creator routes to bounded media-graph RPC loaders. Detail views now render alternate publication/rendition sources, claim provenance and conflicts, archive uncertainty, explicit missing collection members, and uploader/performer/director attribution without inventing global ownership.
- Make local network, retention, subscription, moderation, and AI-analysis policy operational in the app: native-safe screens load and persist through the initialized universal RPC facade, explicit zero-byte ceilings survive optional HRPC fields, profile navigation exposes all three policy areas, startup waits for the platform client instead of reporting a false missing-method error, and privacy copy distinguishes on-device decisions from publisher/index follows, catalog requests, archive records, seeding, mDNS, and IP-address leakage.
- Close final release-blocking production gaps in the CDN cutover: startup now migrates retained legacy publications into attributed publisher catalogs before projection/discovery; the privileged shell provisions and admits exactly one writable local publisher while renderer-selected root semantics are rejected; immutable catalog-commit failures roll back new upload bytes; persisted network policy configures or stops the real discovery, seeding, and archive managers; omitted HRPC ceilings preserve stored values; and source-offload evidence is revalidated under the source mutation lock immediately before deletion.
- Make consumer playback availability an explicit local, expiring evidence contract: healthy requires fresh range-complete proof from two independent authenticated transport identities, partial/union coverage remains limited, archive pledges report durability without claiming network reachability, and generated protocol/types require counters so missing frames cannot masquerade as zero-peer assessments.
- Enforce the relay storage ceiling across protected client application/archive imports as well as evictable cache data: multipart, direct, and yt-dlp staging reserve aggregate peak bytes across retries and restarts, repeated machine submissions reuse one durable idempotency identity, and protocol v9 carries stable TMDB movie/episode coordinates in one appended source envelope so opaque media-graph hashes remain searchable without shifting existing wire flags or duplicating seeds.
- Keep viewer state on the device and delete the last telemetry path. Watch position, completion, and the saved-library flag now live only in the existing encrypted personal store, keyed by media identity and resolved across a viewer's own devices by `(playbackGeneration, lamport, writerKey)` rather than wall-clock time, with bounded retention, sticky deletes, and a one-way migration off the old plaintext file/localStorage copy that keeps the source until the encrypted record reads back. Recommendations are computed on-device by one deterministic ranker with an injected clock. Personal-store device pairing is its own surface — single-use invites that expire within five minutes and are consumed before a writer is granted — and revocation rotates forward into a fresh encrypted epoch while the abandoned one is frozen, unpaired, and taken off its discovery topic, so a revoked device can neither read nor write what follows. The 32-byte secret is generated and held only by the platform vault: there is no plaintext fallback, a device that cannot prove durable custody stays local with pairing disabled, and no response but the pairing redeem carries the secret. Publisher-channel pairing moved into Developer Settings → Studio, and the publisher-visible watch-event log with the backend recommender RPCs (`log-watch-event`, `get-recommendations`, `get-video-recommendations`) is gone, so no relay, publisher catalog, or archive record can carry raw viewing history.
- Make participation one resource-policy decision instead of a promise. A fresh install is Balanced: a 20 GiB cache ceiling, a 1 GiB rolling-24-hour upload ceiling, a 5 Mbit/s outbound cap, upload while a title is playing and for ten minutes after, and opportunistic background work capped at fifteen minutes per session and sixty per rolling day. That outbound cap is a real rate rather than a label — the scoped transport meters content bytes through a token bucket refilled at the decided rate, defers a block that would exceed it instead of answering "unavailable", refuses outbound entirely at zero, and reports the rate it is actually applying, while the byte budget no longer keeps a rival daily ceiling. Background work additionally requires an unmetered network, OS permission, a nominal or fair thermal state, at least half battery or external power, and the greater of 2 GiB or ten percent of the disk free. Every one of those is an OS categorical signal, never inferred: a signal that is read and comes back bad stops every kind of contribution, and a signal the platform cannot read at all stops only the opportunistic background work. The app reports what it can actually read — the background-execution entitlement a live media session provides, free and total disk, and battery and charging state on the desktop shell — throttled, deduplicated, and re-reported on lifecycle, network, and power changes; metered state, thermal state, and native battery level have no platform module in this build, so they are omitted rather than invented. Mobile backgrounding that cannot legally run work suspends the transport instead of pretending to seed, and the rolling upload and background ledgers now survive a restart instead of handing the device a fresh gigabyte. Data Saver contributes only while you watch, Help More raises your own ceilings without relaxing a single device or OS limit, and no mode ever creates an archive pledge — while an archivist that never plays anything can still accept one. Seeding, the byte budget, archive reservations, and playback all consume that one decision, the viewer sees whether the device is eligible, actively uploading (measured in bytes that really moved), or suspended and why, and the exact byte ceilings stay in Developer Settings.
