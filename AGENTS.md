# PearTube Development Guide

PearTube is a decentralized CDN and debrid provider on the Holepunch stack. The core is deliberately small: the Holepunch modules do the heavy work, and PearTube glues them together. Keep it under 1,000 lines.

## Agent Instructions

Builds, installs, and deploy commands may be run when explicitly requested.

## Layout

|File|Purpose|
|---|---|
|`src/index.js`|`createNode`: Corestore, Autobee tracker + `apply`, 1-Hypercore-per-video `Hyperblobs` (`512 KiB` blocks at `blockOffset: 0` with lazy Corestore wakeup, plus backwards-compatible legacy shared `blobSlots` reads), `rechunkLegacyBlobs` (`foreground` override, non-blocking clear), Hyperswarm, `search` / `put` / `append` / `publish` / `remove`, and `setLan` to swap LAN discovery without restarting the node. `search` returns one result per file (`id` + `sha256`), picking owned, then most cached, then a per-video core, then the founder's copy: writers that were reset leave copies nobody stores, which the tracker rules let only their writer remove|
|HTTP Range streaming|Stock [`hypercore-blob-server`](https://github.com/holepunchto/hypercore-blob-server) (reads via `hypercore-byte-stream`: `core.seek` then a linear `core.download` range) on a Corestore session in `src/index.js`, and a token-protected LAN instance in `src/cast.js` for TV receivers. `/v1/blob` in `src/http.js` proxies to it over loopback for the same-origin web player|
|`src/acquire.js`|Private job queue: fetch a source (a page link through `yt-dlp` on every attempt, since its media URLs expire), `put` it into a dedicated `512 KiB` per-video core, save the announce, `append` it durably, and `repointBlob` on legacy slot migration. Stored in `jobs.json`, never in the Corestore|
|`src/settings.js`|Relay settings: env var, then `settings.json` (private, `0600`, beside `jobs.json`), then default. Every key is flagged `live` or restart-only; env-set keys are read-only (`409`). Secrets and tokens inside URLs never leave the file: views carry `{ref, label}`, and `#n` keeps a stored URL on update. `bin/relay.js` reads every non-bootstrap option through it and applies live ones (`setLan`, `setAllowedPeers`, `mirror.configure`). It also saves a founded tracker's key as `tracker` (`remember`): `createNode` keeps its own tracker primary only when given that key or no saved sources, so a bare-started relay that follows a channel would otherwise lose its library on the next start|
|`src/identify.js`|What a link holds, before acquiring it: a direct file (name parsed for title, year, `SxxEyy`, resolution, codec, audio) or a page read by `yt-dlp -J` (title, uploader, length, thumbnail). Movie- or episode-like names get Cinemeta suggestions (`PEARTUBE_CINEMETA_URL`); an exact title and year is `match`. Accepted ids are `imdb:tt…` / `imdb:tt…:sNNeNN` with `Name Year` / `Name S01E02` titles, the shapes MediaStorm searches for; anything else is a `clip:` id. Imported by `bin/relay.js` only, so the apps' worklet never packs `bare-subprocess`|
|`src/http.js`|One port: the UI at `/`, `/v1` API (including `/v1/settings`, and `/v1/identify` + `/v1/poster/:tt` when the relay provides them), `/v1/blob` same-origin HTTP Range blob streaming, and `/web/*` WASM player assets|
|`src/ui.js`|The relay web UI (one HTML string): Library (one add box for links, pages and `peartube://` links, with identification preview; folder, feed and channel-copy panels; jobs; a poster grid filtered by kind, 60 tiles at a time and redrawn only when its contents change, with a details sheet listing a show's episodes by season), Channels, Sharing (peers, kept copies, HiveRelays, Stremio/M3U), TV (pair, remote, browser TV) and Settings tabs. Plugins appear only as user intents, never by id; light and dark themes; in-browser `peartube-media` WebAssembly playback|
|`web/`|Browser WebAssembly player (`peartube_web.wasm`, `sh web/build.sh` -> `web/assets/`, not part of the core line budget): compiles `peartube-media`'s containers, software decoders, surround downmixer, subtitle decoders, and low-latency CMAF fMP4 muxer to `wasm32-unknown-unknown` (`+simd128`) inside a Dedicated Web Worker. `src/decode_order.rs` is the native player's decode-order repair vendored at the pinned media revision and wrapped around every demuxer `pt_open` builds: H.264/HEVC files whose MP4 carries no `ctts` get presentation timestamps from picture order counts before the software decoder, WebCodecs, or the MSE muxer reads them. The Worker keeps six 2 MiB blocks (12 MiB, three in flight) of read-ahead in a 64 MiB ring: a 15 Mbps title decodes at ~3.8x realtime while filling its buffer, and a shallower window fell through to the blocking sync read, freezing the frame clock and dropping pictures once a read took 300 ms. The Worker also drains its queue estimates at wall speed and re-pumps on its own timer when the page's playback credits stop: those credits ride the page's `requestAnimationFrame`, so a hidden, unfocused, or occluded window used to leave the buffers "full", stop decoding, and pause playback after a few seconds (the UI E2E hides a clip for 12 s and now keeps its sound). Bitmap subtitle decoders (`dvd_subtitle`/PGS/DVB) are created with the video stream's dimensions, not the subtitle stream's absent or dummy size, so a DVD cue authored at 758,709 on a 1920x816 picture paints inside the canvas instead of falling off a 720x576 default. Software video is drawn by the page-side GL canvas, not the Worker's OffscreenCanvas: the Worker's render loop measured ~18 of 24 pictures on Batman's VC-1 where the page path holds 24 over the same relay, and the page path carries the detected letterbox crop too (Batman's 1080-row frame crops to 1920x801, so the picture fills the stage width). The clock text and seek bar are written only when their formatted value changes; rewriting the same text node every animation frame made the clock shimmer. On every return the page hard-snaps the MSE element to the audio clock (a background-muted `<video>` and rapid hide/show left it drifting) and drops stale software pictures, and a click on an unfocused window (or within 900 ms of returning) does not toggle play — it only focuses the window. The page owns read-ahead: it fetches 2 MiB blocks with a 6 s timeout and retry and posts them to the Worker, and the Worker's own fetch loop is gone so the two never starve the browser's six connections; a miss still falls back to a 2.5 s sync Range read (never more), and an empty body is an error, not an end of stream. A picture stalled >1.2 s shows "Buffering…". Hidden pictures are retained in a 72-frame ring (the newest is the live one, so the first tick after return draws instantly — measured ~130 ms) instead of being discarded; the MSE SourceBuffer keeps filling while hidden and the element is snapped inside the live buffered range. The Worker's wasm heap measured flat at 29.6 MB over 70 s visible and 60 s hidden, with the block cache (32 x 2 MiB) and buffer pools bounded — the leak was JS-side picture queueing, not the Rust engine The crate root denies `unsafe_code`: `ffi.rs` (host bridge, allocator, raw-pointer marshalling, SIMD128 loads) and `abi.rs` (the C exports) are the only unsafe, and the demuxers, decoders, mixer and muxer are safe Rust. |
|`src/lan.js`|Optional zero-wrapper LAN discovery directly over an isolated ephemeral `HyperDHT` (`port: 0`) + mDNS (`bonjour-service`), stamping each peer's advertised address (`h`) so peers dial directly rather than an mDNS reflector, rebrowsing every 10 s for missed Wi-Fi multicast answers, and falling back to dialing from the larger-key side after 3 s when a host firewall blocks incoming UDP. `bin/relay.js` passes it to `createNode` as a factory; `lanAddress` picks Wi-Fi/Ethernet IPv4 and `interfaceAdapter` pins multicast to that interface|

## Rules

- The Corestore holds only public data (tracker + blobs). Replication serves any stored core a peer can name. Secrets, source URLs and headers stay in private files.
- `apply` is the only gate on the tracker. It must stay deterministic: no clock, no randomness, no I/O. A writer may only add or remove entries under its own writer key.
- Keep Autobee `fastForward: false`. Fast-forward adopts a peer's built view without running `apply`, which lets a forging peer plant entries under other writers' keys (covered by a test).
- A tracker write counts only once it is in the local oplog; an unsynced joiner's optimistic write lives in memory until first sync.
- Connect peers with `tracker.replicate(conn)`, not `store.replicate(conn)`; only the former attaches Autobee's wakeup protocol.
- Announce at most 24 content blobs (two swarm topics each). `status()` must never join a content topic: it is polled every few seconds, and joining there churned the DHT and evicted the titles the relay seeds. Content beyond the cap rotates one complete copy every 20 s, and eviction takes the least recently served blob (touching an announced blob on re-join), owned or cached.
- Give Autobee a namespaced store, and have a new tracker's founder append once before relying on others' optimistic writes.
- Pin `autobee` exactly; it is experimental.
- Use the Holepunch libraries (Hypercore, Corestore, hypercore-storage, Hyperswarm, HyperDHT, hypercore-blob-server) through their public API only, unmodified from npm: no monkeypatching, private methods, private fields (`core.core`, `replicator`, `bitfield`, `store.cores`, `_needsUnannounce`) or patched copies. Count and check local blocks with `core.count()` / `core.has()`, set replication windows with the `inflightRange` open option, and reach storage through the `CoreStorage` instance the node owns. No router rules (OPNsense) either. Blind relays (`relayThrough`) are optional; nothing may depend on one.
- Plugin Protomux channels (`hiverelay-seed`, `peartube/bulk-busy`) register `mux.pair()` on every connection. Protomux rejects an open for an unpaired protocol, so without it a side that attaches later never gets the channel.
- Never pause a replication connection (`conn.pause()`) for more than a moment, and never pause a PearTube relay: a connection paused for a few seconds loses its Hypercore peers and downloads on it stall for good. Relays coordinate backfill with `peartube/bulk-busy` instead; the pause cap is only for HiveRelays.
- Open owned video cores' write sessions with `active: false` (`put`). An owned core never downloads; an active write session makes it report "downloading" for Hypercore's 20-40 s linger, and a peer whose channel closes when Corestore collects the at-rest core then never reopens it.
- Autobee emits `'update'` only on an interrupt. To hear about view changes, pass `onchange` to `createNode`, which runs from Autobee's `update` handler.
- Don't add a machine API field without updating every client in the same change. MediaStorm is the proof client.
- Prefer deleting code to adding it. Old platform code is at tag `archive/v0.3.0-platform`.
- `src/index.js` also runs under Bare, in the apps' worklet: no Node-only imports there. Map `node:` builtins to `bare-*` in `package.json` `imports`, except `node:crypto`, which goes to `worklet/crypto` (SHA-256 only).
- The Android and macOS worklet runs on QuickJS: no `Intl`, and guard V8-only APIs such as `Error.captureStackTrace`. Keep `worklet/patches/libqjs-function-source.patch` until libqjs ends its CommonJS wrapper on a new line; without it the worklet dies loading bonjour-service, which `test/desktop.e2e.js` catches.
- Keep `worklet/patches/libqjs-deferred-release.patch`. QuickJS frees an object as soon as its last reference goes, but addons built for V8 release a reference and then touch memory that object owned (jstl's `js_persistent_t::reset()`). Without the patch, udx-native's DNS lookup crashes the worklet whenever HyperDHT resolves a bootstrap host by name. `test/desktop.e2e.js` names its bootstrap nodes `localhost:<port>` to catch it.
- Keep the Android app's `minSdk` at 29: the QuickJS bare-kit calls `timespec_get`, new in API 29, and the player calls NDK media functions added in 29. Both apps' version is `package.json`'s; releases bump it there.
- Keep the Android app's native libraries uncompressed in the APK (`jniLibs.useLegacyPackaging = false`). Android then loads them from the APK; compressed, it unpacks a second copy at install, which made the Dioxus app take 61 MB on the phone for an 18.7 MB APK. bare-kit loads the worklet's addons by file name, which works from the APK.
- Keep mimalloc as `libpeartube.so`'s global allocator (`android/native/src/lib.rs`). The software decoders allocate and free a lot each frame: on a Pixel 5a, 720p XviD took 23 ms a frame with Android's own allocator and 11 ms with mimalloc, and the MPEG-4 Part 2 decoder's second rebuild thread made decoding slower with Android's allocator. It uses local-dynamic TLS because the app loads the library with dlopen.
- Pin `gpui-kit` exactly: it pins its own GPUI snapshot, and GPUI's API changes between snapshots.
- Keep the Mac app's picture in its own NSView under GPUI's view (`desktop/src/video.rs`), with the window transparent only while a video plays. A layer inside GPUI's view would be drawn over by GPUI's Metal layer, and a view above it would cover the controls.

## Testing

- Never write unit tests after you write code.
- Highly prefer E2E tests as the sole testing mechanism. Use them to verify complex features work. At the end of E2E tests, produce a verifiable and repeatable artifact.
- Phone tests drive only the app. When a system window is in front (a permission prompt, Android's fullscreen notice), stop and ask the user to answer it; never tap it or send it keys.
- If you must test a system in isolation, first write down all the ways it could fail, then write the code.

## Installing a Relay on a System

Follow `README.md` (`### Install on a system (agent quickstart)`) when asked to stand up `peartube-relay`:

- **Environment fit**: Real Linux/macOS hosts, NAS boxes, VPSes, and self-hosted remote `codex` CLI / SSH sessions work, provided command sandboxes (`codex-network-proxy`, Landlock/Seatbelt) are escalated so `udx-native` can open raw UDP sockets and the service is detached under Docker (`--restart unless-stopped`), `systemd`, or `launchd` (never leave `npm start` attached to an agent shell turn). **OpenAI-hosted Codex Cloud VMs (`Work in > Cloud`) cannot run a public/LAN relay**: their HTTP/HTTPS-only proxy blocks raw `HyperDHT`/`UDX` UDP even over Tailscale, exposes no inbound ports, and suspends VMs between turns—use `createTestnet()` on `127.0.0.1` for tests or deploy `ghcr.io/ayooooo123/peartube-relay:latest` to a real host.
- **Required settings**: Set `PEARTUBE_STREAM_HOST=<reachable-ip>` (never leave `127.0.0.1` for remote viewers), set `PEARTUBE_LAN_HOST=<lan-ipv4>` on LAN hosts (`--network host` in Linux Docker so mDNS `224.0.0.251:5353` and ephemeral UDP cross out of the container), and set `PEARTUBE_API_TOKEN=$(openssl rand -hex 32)` on any non-loopback network (`0600` env file, `0700` `PEARTUBE_STORAGE`).
- **Native host dependencies**: Node `>= 22`, `git`, and on Debian/Ubuntu `libatomic1` (`rocksdb-native` links `libatomic.so.1`). `npm ci --omit=dev` links `node_modules/.bin/bare` directly to the native `bare-runtime` binary so `ExecStart=.../node_modules/.bin/bare .../bin/relay.js` receives `SIGTERM` cleanly without a Node wrapper.
- **Verify before yielding**: Poll `GET http://127.0.0.1:8174/v1/status` for 64-hex `tracker` + `channel` keys and check `GET /manifest.json` (`200 OK`).

## Troubleshooting

No peers: check both NATs. HyperDHT aborts with `HOLEPUNCH_DOUBLE_RANDOMIZED_NATS` (reported as `HOLEPUNCH_ABORTED`) when both sides are randomized; forward a UDP port (`PEARTUBE_DHT_PORT`) or use `PEARTUBE_RELAY_THROUGH`.

Slow first connection on a local testnet: every peer is on 127.0.0.1, which HyperDHT will not holepunch, so two peers connect only once one of them passes dht-rpc's NAT check and reports itself open. That check can take minutes after a failed first try; a fresh testnet usually connects in about 25 seconds, which is why the E2E tests wait up to 60–120 seconds.
