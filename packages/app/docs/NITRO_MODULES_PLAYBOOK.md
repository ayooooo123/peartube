# Nitro Modules Playbook (PearTube)

This doc covers practical patterns for working with **Nitro Modules** in this repo, with emphasis on Nitro VLC and Android system integration (MediaSession / PiP).

## What "Nitro Modules" means here

- A native module/view with a JS/TS surface, typically generated/bound via Nitro tooling.
- In PearTube we use Nitro for the VLC view (`react-native-nitro-vlc`) and bridge it to system features (MediaSession, PiP).

## Key Principles

### 1) JS may be asleep; make critical playback controls native

Home screen media managers and notifications can invoke play/pause while the app is backgrounded.

If resume is implemented only via JS events:
- the UI may update eventually, but playback might not resume promptly.

Pattern used here:
- Provide a native entry point that directly pauses/resumes the native player.
- Call it from the MediaSession callbacks.

Example:
- `HybridNitroVLCView.setAllPlaybackPaused(paused)` via reflection.

### 2) Registry fan-out for multi-view correctness

For view-wide operations (PiP mode, PiP window size, pause/resume), a static registry is practical:

- Keep a `ConcurrentHashMap<id, WeakReference<View>>`.
- Provide `@JvmStatic` helpers:
  - `setAllPipMode(active)`
  - `setAllPipWindowSize(widthPx, heightPx)`
  - `setAllPlaybackPaused(paused)`

### 3) Main thread only for view mutations

Any changes to `TextureView` (matrix/translation) must happen on the main looper.

Pattern:
- If not on main thread: post to main (`runOnUiThread { ... }`).

### 4) Prefer transforms over LayoutParams for video surfaces

If you need to change how video appears while keeping the SurfaceTexture stable:
- use `TextureView.setTransform(Matrix)`
- use `translationX/Y`, `scaleX/Y` where appropriate

Avoid:
- frequent LayoutParams updates
- resizing the view during PiP transitions

## Android Build Hygiene

### Ignore externalNativeBuild outputs

`android/.cxx/` is generated by Gradle/CMake/Ninja (externalNativeBuild). It must not be tracked.

Repo rule:
- `/.gitignore` should include:
  - `**/android/.cxx/`

If already tracked:
- remove from index with `git rm -r --cached <path>`.

## Notification / MediaSession actions

Make notification actions deterministic:
- Prefer explicit `PendingIntent.getService(... ACTION_...)` to your own playback service.
- Avoid relying on generic MediaButtonReceiver intents if you already have a service action pipeline.

Files to know:
- `packages/app/modules/expo-media-session/android/src/main/java/to/holepunch/modules/mediasession/MediaPlaybackService.kt`
- `packages/app/modules/expo-media-session/android/src/main/java/to/holepunch/modules/mediasession/MediaSessionModule.kt`

## Debugging Tips

Useful log filters:

```bash
adb logcat | grep -E "(NitroVLC|MediaSession|MediaPlaybackService|PipBridge)"
```

Typical failure signatures:
- "drag fixes it" => recompute logic only runs on config changes; add reapply on view size changes.
- flashes during resize => `updateVideoSurfaces()` is firing mid-resize; cancel/defer/avoid during transitions.
